# Навчальна платформа тестування

Flask + SQLite застосунок для створення та проходження кількох тестів. Викладач
керує тестами в кабінеті, редагує запитання, налаштовує час, відкриває та закриває
приймання і копіює студентське посилання. Під час першої ініціалізації база
отримує тест УО-6 і тест УО-4 із 20 запитань та таймером 40 секунд на кожне.

## Локальний запуск

Потрібен Python 3.10+ з підтримкою `hashlib.scrypt`:

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
export DATABASE="$PWD/instance/testing.sqlite"
export PUBLIC_URL=http://127.0.0.1:5055
export COOKIE_SECURE=0
export LOCAL_TEACHER_LOGIN_ENABLED=1
.venv/bin/flask --app app init-db
.venv/bin/flask --app app create-teacher --credentials-file .credentials/teacher.txt
.venv/bin/flask --app app run --port 5055
```

Відкрийте `http://127.0.0.1:5055/` і скористайтеся «Вхід викладача».
Логін `admin@student.karazin.ua`, випадковий пароль зберігається в указаному
закритому файлі. Це локальний обліковий запис платформи, не університетський
акаунт. Не відкривайте HTML як файл: сервер потрібен для авторизації та збереження
відповідей.

`flask init-db` створює структуру бази та виконує повторно безпечну міграцію.
Для наявної бази запустіть цю команду перед запуском нової версії. Міграція додає
посилання й стан тесту, зберігає наявні питання, ключі, спроби та відповіді,
а email наявних спроб копіює в поле учасника. Вона не перераховує оцінки. Якщо
використовується production база, УО-4 додається один раз як окремий відкритий
тест; його посилання має вигляд `/t/uo4-2026`.

## Робота викладача

У кабінеті створіть тест, задайте назву та опис, додайте запитання і ключі,
перегляньте тест як студент та збережіть. Кожен тест має постійне посилання
`/t/<код>`, яке можна скопіювати з картки тесту. Чернетка за посиланням не
показується. Відкрийте тест, коли ключі перевірені; закриття припиняє лише нові
спроби, активні учасники можуть завершити свої спроби.

Редагування відкритого тесту автоматично закриває його для нових спроб. Спроби
зберігають власний знімок запитань, ключів і таймера, тому подальші правки не
змінюють вже розпочаті або завершені результати. У розділі результатів можна
шукати учасників, переглядати відповіді та завантажувати CSV окремого тесту.

Для нового тесту таймер за замовчуванням становить 20 секунд на запитання; його
можна вимкнути або встановити від 5 до 3600 секунд. Наявний тест УО-6 зберігає
20 секунд; для УО-4 встановлено 40 секунд. Кожне запитання дає один бал.

## Запитання та оцінювання

Конструктор підтримує:

- **Одна відповідь:** учасник вибирає один варіант. Можна позначити кілька
  прийнятних варіантів ключа, наприклад для граматичних альтернатив.
- **Кілька відповідей:** учасник вибирає всі правильні варіанти. Бал нараховується
  лише за точного збігу з ключем; часткових балів немає.
- **Короткий текст:** викладач задає допустимі відповіді. Перевірка не враховує
  регістр і зайві пробіли; пунктуація та інші символи мають збігатися.

## Участь студентів

Студент відкриває пряме посилання, вводить ім’я, прізвище та будь-яку синтаксично
коректну email-адресу. Email нормалізується без урахування регістру та є
ідентифікатором учасника. Сервер зберігає одну спробу на адресу для кожного тесту.
Для прямого посилання браузер також зберігає хеш адреси в `localStorage` і не дає
почати цей тест у тому самому браузері з іншою адресою. Очистка даних браузера
може зняти цей додатковий бар’єр; серверний ліміт на ту саму email-адресу лишається.

Адреса не підтверджується листом або університетським входом. Тому учасник може
ввести чужу адресу або помилитися в ній; під час повернення потрібно ввести ту
саму адресу. Не поширюйте результати за email як доказ особи.

## Обліковий запис викладача

Тестовий парольний вхід вмикається через `LOCAL_TEACHER_LOGIN_ENABLED=1`.
Пароль зберігається у базі лише як scrypt-хеш. Для реального Google-входу
студентів потрібні окремі OAuth-налаштування; введення email у поточному режимі
не доводить належність поштової скриньки.

## Розгортання на VPS

Приклади systemd і Nginx знаходяться в `deploy/`. Перед розгортанням замініть
шляхи та домен на свої, створіть приватний файл оточення з правами 0600 і
зберігайте SQLite-базу на постійному диску окремо від коду. Запустіть
`flask --app app init-db` перед стартом сервісу. Застосунок має слухати лише
локальний порт за reverse proxy; для Nginx перевірте конфігурацію командою
`nginx -t` перед перезавантаженням.

У цьому репозиторії немає налаштованого хостингу чи production бази. GitHub
зберігає код, але не запускає Flask-застосунок. Для безкоштовного постійного
розгортання потрібен обліковий запис хмарного VPS, наприклад OCI Always Free;
після створення VM задайте `DATABASE`, `SECRET_KEY`, `PUBLIC_URL` та
`LOCAL_TEACHER_LOGIN_ENABLED` у приватному файлі оточення.

## Перевірки для власника проєкту

```sh
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
node --check static/app.js
```

Перевірте в браузері вхід викладача, створення тесту, всі три типи запитань,
відкриття посилання на телефоні та комп’ютері, відновлення активної спроби,
закриття тесту і CSV з різною кількістю запитань.
