# УО-6 · Учебное тестирование

Flask + SQLite, 20 вопросов из `TEST УО-6.docx`, серверный таймер 20 секунд,
одна попытка на аккаунт и кабинет преподавателя. Интерфейс адаптирован
для компьютера и телефона; таймер остаётся сверху при прокрутке.

## Локальный запуск

Python 3.10+ с поддержкой hashlib.scrypt:

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
export DATABASE="$PWD/instance/testing.sqlite"
export PUBLIC_URL=http://127.0.0.1:5055
export COOKIE_SECURE=0
export LOCAL_TEACHER_LOGIN_ENABLED=1
.venv/bin/flask --app app init-db
.venv/bin/flask --app app create-teacher --credentials-file .credentials/teacher.txt
.venv/bin/flask --app app run --port 5055
```

Откройте `http://127.0.0.1:5055/`, раскройте «Тестовый вход преподавателя».
Логин `admin@student.karazin.ua`, случайный пароль находится в указанном
закрытом файле. Это локальный логин платформы, не университетский аккаунт.
Не открывайте HTML как файл: сохранение ответов и авторизация требуют сервера.

В кабинете доступен предпросмотр всех вопросов с таймером и результатом.
Он явно помечен, не создаёт попытку и не сохраняет учебные результаты.

## Google для студентов

1. Создайте OAuth web application в Google Cloud; разрешите доступ нужным
   университетским пользователям (внешнее приложение, если проект не принадлежит
   университетской Google Workspace organization).
2. Настройте consent screen, scopes `openid email profile` и точный redirect:
   `https://gsse.work/testing/auth/google/callback`.
3. В закрытом серверном `/etc/uo6-testing.env` заполните `GOOGLE_CLIENT_ID`
   и `GOOGLE_CLIENT_SECRET`. Не отправляйте секреты в Git.
4. Проверьте `GOOGLE_HD`: Workspace claim может отличаться от email-домена.
   Email студента должен иметь точный домен `student.karazin.ua`.
   Google-преподавателей можно разрешить отдельно через `GOOGLE_TEACHER_EMAILS`.
   Временный локальный admin не получает Google-роль автоматически.
5. Перезапустите `testing.service`, выполните реальный вход учебного аккаунта.
   При ограничениях Workspace администратор университета должен одобрить приложение.
6. В кабинете просмотрите вопросы и подтвердите ключи, затем откройте приём ответов.

Справка: https://developers.google.com/identity/openid-connect/openid-connect

Без OAuth настроек вход студентов недоступен. Приложение не подменяет его
непроверенным вводом email. Чтобы отключить тестовый парольный вход, задайте
`LOCAL_TEACHER_LOGIN_ENABLED=0` и перезапустите сервис. Существующие локальные
сессии тоже потеряют доступ; предварительно проверьте Google-вход преподавателя.

## Содержание теста

Исходные ключи сохраняются в `source_correct`; предлагаемые уточнения —
в `suggested_correct`. Перед открытием преподаватель подтверждает №7 (b/c),
№10 (d), №16 (b). №7 допускает два грамматически корректных варианта,
но участник выбирает один ответ. В интерфейсе преподавателя отмечены расхождения.
Версия вопросов копируется в попытку; последующая правка ключа её не меняет.

## VPS

Выделенный сервис `testing.service`, пользователь `uo6-testing`, порт
`127.0.0.1:5056`, код `/opt/uo6-testing/current`, база
`/var/lib/uo6-testing/testing.sqlite`. Префикс `/testing` обслуживается
отдельным Nginx location внутри существующего HTTPS server `gsse.work`.
Nginx перезаписывает forwarded headers; приложение доверяет одному proxy
только при `TRUST_PROXY=1`. Порт приложения нельзя открывать наружу.

Конфигурации находятся в `deploy/`. Перед reload обязательно `nginx -t`.
Приватный файл окружения имеет права 0600, системный пользователь приложения
не может менять код. Пароль хранится только scrypt-хешем; сессии — на сервере.

`testing-backup.timer` делает ежедневные локальные копии SQLite с проверкой
целостности, хранит 14 дней. Копии лежат в `/var/lib/uo6-testing/backups`.
Они не защищают от потери VPS; при необходимости настройте внешнюю копию.
Восстановление: остановить сервис, сохранить текущую базу, восстановить
проверенную backup-копию в отдельный каталог без старых `-wal`/`-shm`,
установить владельца `uo6-testing` и права 0600, запустить сервис и проверить вход.

## Проверка

```sh
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
node --check static/app.js
```

Проверяются сессии, CSRF, ограничение входа, роли, конкурентный старт,
дедлайны, пропуски, повторные запросы, CSV, префикс URL и backup/restore.
Google дополнительно требует реальной проверки после подключения credentials.
