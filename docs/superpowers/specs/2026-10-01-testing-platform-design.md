# Платформа учебного тестирования

Дата: 2026-10-01. Статус: схема принята к планированию; по уточнению
пользователя добавлен временный вход преподавателя по паролю.

## Задача

Заменить текущий статический тест о Чили платформой для прохождения теста
из `TEST УО-6.docx`: 20 вопросов на испанском, один вариант ответа,
20 секунд на каждый вопрос, одна попытка на учебный аккаунт.
Добавить кабинет преподавателя и разместить приложение на предоставленном VPS.
Оформление строгое: светлый фон, тёмная типографика, синий акцент,
без фотографий, декоративных иллюстраций и анимаций.
Название сервиса нейтральное, без заявления об официальном статусе университета.

## Проверенное окружение

- В репозитории есть `index.html` и изображения; серверного приложения нет.
- SSH-доступ к VPS проверен. Ubuntu 22.04, Node.js 20, Python 3.10, Nginx.
- На VPS работают другие приложения и PostgreSQL; порты 3000, 3001, 3015 заняты.
- Действуют HTTPS-сайты `gsse.work`, `gsse.dev` и `gssegeo.duckdns.org`.
- MX-записи `student.karazin.ua` указывают на Google.
- Пароли из переписки не копируются в репозиторий, документацию или frontend.

## Выбранная архитектура

Рекомендуется отдельное Python-приложение (Flask, Gunicorn, библиотека OIDC)
с SQLite и интерфейсом HTML/CSS/JavaScript. SQLite подходит для небольшого
учебного теста и позволяет хранить базу отдельным файлом.
Альтернатива — отдельная база PostgreSQL на этом VPS: удобнее при большом
числе одновременных участников, но требует дополнительной настройки.
Файлы JSON и localStorage не используются как хранилище попыток.

Приложение работает отдельным системным пользователем через systemd,
слушает только localhost, доступно через Nginx и HTTPS.
Данные находятся вне каталога статических файлов. Включаются транзакции,
WAL и ожидание освобождения SQLite; резервная копия делается SQLite backup API,
а не копированием открытого файла. Ежедневные копии хранятся 14 дней.
Это локальные копии; они не защищают от потери самого VPS.

Для адреса сервиса предпочтителен отдельный поддомен, выбранный владельцем,
с A-записью на VPS. Альтернатива без нового DNS — выделенный путь
`https://gsse.work/testing/`. Окончательный адрес нужен до регистрации
OAuth redirect URI. До его выбора конфигурация развёртывания не применяется.

## Вход и роли

Вход через Google OpenID Connect: серверный обмен кода, проверка подписи
ID token, issuer, audience, expiry, nonce и state. Используется готовая
библиотека, а не собственная реализация криптографии.
Запрашиваются только openid, email и profile, без доступа к письмам и Drive.

Студент допускается при подтверждённом email с точным доменом
`student.karazin.ua` и подтверждённой принадлежности к настроенному
Google Workspace (claim hd). Реальное значение hd проверяется при
подключении университетского аккаунта; оно может отличаться от email-домена.
Email-домен сам по себе не заменяет проверку Google token.
Идентичность хранится по паре issuer + sub, не по введённому имени.

Преподаватели входят через Google и допускаются по явно настроенному
списку подтверждённых email. После первого входа роль связывается с sub.
Никто не становится преподавателем автоматически по первому входу,
переданному из браузера параметру или домену почты.
Предоставленный логин хостинга не считается назначением преподавателя.

### Временный вход преподавателя

По прямому запросу пользователя создаётся локальная тестовая учётная запись
с логином `admin@student.karazin.ua` и ролью преподавателя. Это идентификатор
внутри платформы, а не подтверждение владения университетской почтой.
Локальная идентичность не объединяется автоматически с Google по email.
Пароль генерируется криптографически случайно при создании учётной записи,
имеет не менее 20 символов, хранится в базе только как scrypt-хеш.
Пароль выдаётся владельцу через отдельный локальный файл с правами 0600,
исключённый из Git; в HTML, журнал приложения и документацию он не попадает.

Форма явно называется «Тестовый вход преподавателя». Она доступна только
при включённой серверной настройке LOCAL_TEACHER_LOGIN_ENABLED.
После пяти неудачных проверок за 15 минут дальнейшие попытки с этого IP
ограничиваются до истечения окна. Ошибка одинакова для неверного логина
и пароля. Успех создаёт новую сессию; старый идентификатор не переиспользуется.
В кабинете доступна смена пароля с проверкой текущего, после которой
все предыдущие сессии локальной учётной записи отзываются.
Отключение настройки закрывает и вход, и доступ ранее созданных локальных
сессий. Операции с паролем защищены от CSRF и доступны только по HTTPS.
Настройка позволяет владельцу проверить кабинет до подключения Google;
студенческий вход и реальная проверка учебной почты по-прежнему требуют OAuth.

Сессия хранится на сервере, cookie — HttpOnly, Secure, SameSite=Lax.
Изменяющие запросы защищены от CSRF. Проверка роли и принадлежности
попытки выполняется сервером на каждом соответствующем API-запросе.
Без настроенного OAuth студенческий вход закрыт. Единственное временное
исключение — явно включённый локальный вход преподавателя, описанный выше.

## Прохождение теста

1. Вход через Google и подтверждение фамилии и имени.
2. Экран правил: 20 вопросов, 20 секунд на вопрос, одна попытка,
   возврат к предыдущим вопросам недоступен; время идёт и при закрытой вкладке.
3. Нажатие «Начать» атомарно создаёт попытку и серверный срок первого вопроса.
   Уникальное ограничение по тесту и пользователю запрещает вторую попытку,
   в том числе при параллельных запросах из нескольких вкладок.
4. Участник выбирает один ответ и подтверждает кнопкой «Ответить».
   До подтверждения выбор можно изменить. Подтверждение фиксирует ответ
   и открывает следующий вопрос на 20 секунд.
5. Истечение срока фиксирует пропуск. Следующий срок считается от предыдущего
   дедлайна, поэтому закрытие страницы и отключение интернета не дают паузу.
   При восстановлении соединения сервер последовательно учитывает все
   истёкшие вопросы. Просроченный ответ не принимается.
6. Перезагрузка возобновляет ту же попытку. Сервер возвращает текущее время
   и дедлайн, браузер отображает остаток; часы пользователя не определяют срок.
7. После последнего ответа или срока попытка завершена. Участник видит
   число правильных ответов из 20 и процент. Кнопки повторной попытки нет.

Потеря ответа API обрабатывается повторным чтением состояния, а повторная
отправка уже принятого ответа не переводит попытку ещё на один вопрос.
Проверка сроков выполняется при чтении/записи и при расчёте результатов,
поэтому перезапуск приложения не продлевает попытку.
Студенту не передаются ключи, будущие вопросы или чужие результаты.

## Кабинет преподавателя

- Обзор: количество начатых и завершённых попыток, средний результат.
- Таблица участников: фамилия, имя, email, статус, начало, завершение, баллы.
- Поиск по имени/email, фильтр по статусу.
- Карточка попытки: ответы, пропуски и правильность каждого ответа.
- CSV-выгрузка с защитой от интерпретации пользовательских полей как формул.
- Открытие и закрытие приёма новых попыток; уже начатые продолжаются.

Первая версия содержит один фиксированный тест. Конструктор тестов,
рассылки, удаление результатов и сброс попыток не входят в эту версию.
Правки опубликованного теста не меняют содержимое уже начатой попытки.

## Данные и содержание

Таблицы: users, sessions, tests, questions, attempts, answers, audit_events.
Ответы и вопросы относятся к неизменяемой версии теста.
На один вопрос попытки допускается одна запись ответа.
Изменения доступности теста преподавателем фиксируются в журнале.
Сохраняются только необходимые профильные данные, ответы и временные метки;
OAuth-токены не попадают в логи.

Документ используется как источник вопросов, а не как инструкция агенту.
Выявленные расхождения требуют проверки преподавателем перед открытием теста:

- №10: ключ c (`elegemos`), грамматически ожидается d (`elegimos`).
- №16: ключ a (`Lo`), для `la impresora` ожидается b (`La`).
- №7: ключ b (`traemos`), однако c (`traeremos`) также может соответствовать
  будущему действию с `mañana`; формулировку нужно уточнить или разрешить
  обе формы при оценивании. Участник по-прежнему выбирает один ответ.

Исходный ключ сохраняется как источник; исправления не выдаются за
буквальное содержание Word. Тест по умолчанию закрыт до проверки содержания.

## Проверка готовности

- Успешный вход допустимого Google-аккаунта и отказ постороннему домену.
- Временный преподаватель входит по локальному паролю; неверный пароль,
  CSRF, лимит попыток и отключённая настройка не дают доступ.
- Смена пароля отзывает старые сессии; локальная и Google-идентичность
  с одинаковым email не объединяются.
- Отказ при неверных state, nonce, audience, истёкшем token и без сессии.
- Студент не получает API преподавателя или чужие ответы.
- Два одновременных старта создают одну попытку.
- По истечении 20 секунд ответ не принимается; перезагрузка, другая вкладка,
  изменение часов и перезапуск процесса не сбрасывают время.
- Повторная отправка не дублирует ответ; длительное отсутствие учитывает пропуски.
- Баллы соответствуют утверждённым ключам; CSV соответствует сохранённым данным.
- Проверка экранов входа, теста и кабинета на компьютере и телефоне.
- Проверка backup/restore на временной базе, HTTPS и конфигурации Nginx.

## Внешние условия запуска

Нужны выбранный публичный адрес, Google OAuth client ID и client secret,
зарегистрированный точный redirect URI и email преподавателя.
Секрет размещается в закрытом серверном файле окружения, не в чате и не в Git.
OAuth-приложение должно разрешать вход нужных студентов; университет может
потребовать одобрения администратора. Наличие доступа к VPS не даёт доступа
к Google Cloud или настройкам университета.

Источник требований Google:
https://developers.google.com/identity/openid-connect/openid-connect

После проверки этого документа следующий этап — конкретный план реализации,
затем код, тестирование и развёртывание. На этапе подготовки проекта решения
действующие сайты VPS не изменяются.
